Container details

Calculation rules

One container per BL / container pair

All duplicate pairs and invalid rows are quarantined before activation. Delivered and Pending use your explicit status mapping; other statuses are Unknown. Delivery rate = delivered ÷ total.

Delivery targets

Overdue = Pending with a target before the assessment date. Approaching includes today through the configured warning window. Missing targets have unknown risk.

Lead time & delays

Lead time = actual Delivery Date minus the chosen actual start date, in calendar days, for Delivered containers. Delay = actual delivery minus target for Delivered, or assessment date minus target for Pending, with a minimum of zero. Missing dates are unavailable.

DEM / DET

Explicit deadlines take priority. An optional confirmed rule uses start + free calendar days, excluding the start day. DEM stops at gate out; DET stops at empty return. Missing stops require an explicit open-state assumption. Future or contradictory events cannot establish charge exposure.

Estimates require confirmed flat daily rates and a currency. Charge days = maximum of zero and end minus deadline. Currencies stay separate. Tiered, combined, business-day and inclusive-start contracts are not inferred.

Source & privacy

Only valid rows feed the dashboard. Source values remain available in container details. Dates are calendar dates; Excel times are ignored in analytics. Changing assessment date does not reconstruct historical source statuses. Files and filters last only while this tab is open. Nothing is sent to a server or saved to browser storage.
